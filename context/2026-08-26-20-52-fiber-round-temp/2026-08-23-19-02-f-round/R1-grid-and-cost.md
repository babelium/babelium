# R1 — 模型网格与成本账(全轴)

**本篇只做两件:把九个模型定成一张有对照结构的网格,把成本按四条轴(GPU / 存储 / 网络 / 时间)全部报出来。不含实验步骤。**

**纪律:凡本篇写的 config 数值,标 ✅ 者为本轮实测(HF `raw/main/config.json`,2026-08-23);标 ⬜ 者未核实,须在跑之前核实并回填。不许拿记忆当事实。**

---

## 一、网格的设计约束(为什么不是「挑九个大模型」)

CC-05 记过:跨家的模型同时换了分词器、数据、架构,故跨家差异归因不到任何单一原因。所以网格要能**分别**锁住变量:

| 对照 | 锁住 | 变动 | 用来测 |
|---|---|---|---|
| 同家跨规模 | 分词器 + 架构 | 规模 | P5(第二项代价随规模下降) |
| 同规模跨家 | 规模 | 分词器 + 架构 | 判据是否跨家可比 |
| 同规模同家跨注意力 | 规模 + 分词器 + 数据近似 | MHA/GQA vs MLA | P6(MLA 第一项更低) |
| 同分词器跨训练 | 分词器 + 架构 + 规模 | 训练过程 | 分词器效应 vs 训练效应 |

第四行是本轮新加的,理由:P1/P2(锚对齐率、不可达 token)是**权重的性质**,而权重同时受词表和训练影响。缺这一行则「AAR 低是因为不绑定」与「AAR 低是因为这家训得不同」分不开。

## 二、网格

### 主梯:Qwen2.5 五点(同家跨规模)

| 模型 | HF repo | vocab | hidden | layers | tie | 状态 |
|---|---|---|---|---|---|---|
| 0.5B | `Qwen/Qwen2.5-0.5B` | 151936 | 896 | 24 | **true** | ✅ |
| 1.5B | `Qwen/Qwen2.5-1.5B` | 151936 | 1536 | 28 | **true** | ✅ |
| 3B | `Qwen/Qwen2.5-3B` | ⬜ | ⬜ | ⬜ | ⬜ | ⬜ |
| 7B | `Qwen/Qwen2.5-7B` | ⬜ | ⬜ | ⬜ | ⬜ | ⬜ |
| 32B | `Qwen/Qwen2.5-32B` | **152064** | 5120 | 64 | false | ✅ |

**梯子里有一个断点,必须当协变量处理而不是忽略:tie 在 0.5B/1.5B 为真、32B 为假。** 于是「第二项代价随规模下降」与「绑定 → 不绑定」在同一条梯子上共变。**这不是可以绕开的**——Qwen 全家都是小模型绑定、大模型不绑定。处理办法两条,都要做:

1. 3B / 7B 的 tie 值决定断点位置,先核实(⬜),把梯子切成两段各自看趋势;
2. **用 P1 的 AAR 作协变量**:若代价随规模下降而 AAR 不随规模系统变化,则下降不归因于 tie。

**第二个断点:32B 的 vocab 是 152064 而其余是 151936,差 128 行。** 这 128 行大概率是对齐补位、从未被训练。**它们会把 AAR 的分母污染 8.4e-4,把「未训练行」混进「不可达 token」。** 处理:AAR 与不可达统计一律在**两个分母**下各报一次(名义 vocab_size、分词器实际 `len(tokenizer)`),差集单列。

### 32B 横切(同规模跨家/跨训练)

| 模型 | HF repo | 角色 | 状态 |
|---|---|---|---|
| Qwen2.5-32B | `Qwen/Qwen2.5-32B` | 主梯顶点 | ✅ |
| Qwen3-32B | `Qwen/Qwen3-32B` | 同家跨代:vocab 151936、hidden 5120、64 层、64:8 GQA、tie false | ✅ |
| DeepSeek-R1-Distill-Qwen-32B | `deepseek-ai/DeepSeek-R1-Distill-Qwen-32B` | **同分词器同架构、训练不同**——第四行对照的实现 | ⬜ |
| Llama 3.x ~32B 档 | ⬜ | **缺**:Llama 无 32B 档(跳 8B→70B) | 见 §3 |

**Qwen2.5-32B 与 Qwen3-32B 是干净的一对**:hidden、层数同,注意力头数不同(40:8 vs 64:8),vocab 差 128。**这一对锁住规模与家族,只变代次**,是网格里最干净的对照,本轮新发现。

### MLA 对照(P6)

| 模型 | HF repo | 关键 config | 状态 |
|---|---|---|---|
| DeepSeek-V2-Lite | `deepseek-ai/DeepSeek-V2-Lite` | MLA:`kv_lora_rank=512`、`qk_nope=128`、`qk_rope=64`、`v_head_dim=128`;MoE:64 专家取 6;首层 dense;vocab 102400;27 层;hidden 2048;tie false | ✅ |
| Qwen3-30B-A3B | `Qwen/Qwen3-30B-A3B` | **非 MLA 的 MoE 对照**:GQA 32:4;128 专家取 8;每层 sparse;48 层;hidden 2048;tie false | ✅ |

**为什么必须配 Qwen3-30B-A3B:** V2-Lite 是 MoE,若拿它对标 dense 的 Qwen2.5-3B,则「MLA 效应」与「MoE 效应」完全共线。配上同为 MoE 的 Qwen3-30B-A3B 后,**MoE 被锁住,只剩注意力机制在变**。两者 hidden 同为 2048,这是巧合但可用。

**残留混淆如实记:V2-Lite 总 16B / 激活 2.4B,Qwen3-30B-A3B 总 30B / 激活 3B,vocab 102400 vs 151936。** 三处不同,故 P6 若出正结果,归因强度只到「这一对上成立」,不到「MLA 使代价降低」。**要更强的归因须同家有/无 MLA 的一对,而公开权重里我不知道有这样一对。这是 P6 的硬上限,不许写成已归因。**

### 分词器族(P3,不需要权重)

## 三、Llama 的两个问题,及处置

1. **权重是 gated。** 本轮 `meta-llama/Llama-3.2-1B` 与 `Llama-3.1-8B` 的 `config.json` 均返回 **HTTP 401**。须先接受许可并配 token,配好后回填 ⬜。**我记忆里的 vocab 128256 / hidden 2048 / 16 层等数值本轮未能核实,一律不许进正文当事实。**
2. **无 32B 档。** Llama 3.x 是 1B / 3B / 8B / 70B / 405B。**故「三家各三档、每家含一个 32B」这个原始设想在 Llama 上做不到。**

处置:**Llama 降为分词器 + 权重级参与(P1/P2/P3/P7),不进 32B 横切。** 32B 那一档由 Qwen2.5-32B / Qwen3-32B / R1-Distill-Qwen-32B 三个填,但**这三个共用 Qwen 分词器族**,故 32B 横切锁住的是规模而**没有锁住分词器多样性**。

**这是网格的一处真实缺陷,不掩饰。** 要在 32B 档做到跨分词器,唯一现成的路是把该档换成 ~30B 附近的异族模型(如 Gemma-2-27B、Mistral-Small-24B 一类),代价是规模不再严格相等。**这个取舍我不替你定:是「32B 严格同规模但同分词器」,还是「24–30B 近似同规模但跨分词器」。两者不能同时要。**

## 四、成本账,四条轴

### 存储(此前完全没进账)

bf16 权重 ≈ 2 bytes/param。

| 项 | 权重 | 说明 |
|---|---|---|
| Qwen2.5 五点合计 | ≈ 0.5+1.5+3+7+32 = 44B params → **≈ 88 GB** | |
| Qwen3-32B | ≈ **64 GB** | |
| R1-Distill-32B | ≈ **64 GB** | |
| V2-Lite(16B 总) | ≈ **32 GB** | 激活少但**权重要全下** |
| Qwen3-30B-A3B(30B 总) | ≈ **60 GB** | 同上 |
| **合计** | **≈ 308 GB** | 不含分词器、不含中间量 |

**关键削减:P1/P2/P7 只要嵌入与 lm_head 两个张量。** safetensors 支持按分片取文件,故这三条预言只需下含 `embed_tokens.weight` 与 `lm_head.weight` 的分片。以 32B 为例:两张 152064×5120 bf16 矩阵 ≈ **1.56 GB/张**,取两张 ≈ 3.1 GB,**而非 64 GB**。**九个模型的 P1/P2/P7 全部合计约 15–20 GB,不是 308 GB。**

**故存储账分两笔:预言 P1/P2/P7 约 20 GB;需要前向的 P4/P5/P6/P8 才要 308 GB。** 前者可以在普通机器上做完。

### 网络

境外机器下 308 GB:按 100 MB/s 约 **0.9 小时**,按 20 MB/s 约 **4.3 小时**。HF 有并发限流,实测通常低于标称。**P1/P2/P7 那 20 GB 在任何带宽下都是分钟级。**

### GPU

| 组 | 需求 | 依据 |
|---|---|---|
| P1/P2/P3/P7/P9/P10 | **零 GPU**(矩阵乘可在 CPU 做;32B 的 152064×5120 转置乘自身是 152064² 输出 = 23e9 元素,**不能整块算,须分块取 argmax**) | Q3 §7 |
| P4/P5/P8(F2/F4) | 32B bf16 权重 64 GB + 激活 → **单张 80GB(A100/H100)可放**;B200(180GB)更宽松 | 纯前向 |
| P6 | V2-Lite 32 GB + Qwen3-30B-A3B 60 GB → 单张 80GB 各自可放 | 纯前向 |
| F6 微调 32B | 全参 bf16 + Adam ≈ 32B×16 bytes ≈ **512 GB 优化器态** → 须多卡或 LoRA | 见 R4 |

**AAR 的计算量必须先算清,否则会被当成「零成本」再犯一次旧毛病:** 32B 上要对每个 $a$ 求 $\arg\max_b\langle e_a,w_b\rangle$,即 152064×5120 与 5120×152064 相乘取行 argmax。FLOPs ≈ 2×152064²×5120 ≈ **2.4e14**,即 240 TFLOPs。CPU 上按 200 GFLOPs 算约 **20 分钟**;单卡按 100 TFLOPS 算约 **2.4 秒**。**故它零 GPU 但不零算力,九个模型合计 CPU 上是小时级。** 分块须按 $b$ 分块并保持全局 argmax,不许分块后各自取局部 argmax 再合并错。

### 时间(墙钟,估)

核实 config 与分词器族 0.5 天;P1/P2/P7 实现 + 跑 1 天;F3 实现 + 跑 1.5 天;F2/F4 实现 0.5 天、跑(九模型 × 语料)1 天;F5 0.5 天;F6 单列。**设备到位前可结清的部分约 3 天。**

## 五、本篇结论

- 网格定为 **Qwen2.5 五点主梯 + 32B 三横切 + MLA 一对 + 分词器十族**,共 9 个权重模型。
- **两处断点必须当协变量**:tie 在主梯上共变;32B 的 vocab 多 128 行。
- **两处硬上限,不掩饰**:P6 的归因只到「这一对」;32B 档做不到跨分词器,取舍待定。
- **成本账的关键修正:P1/P2/P7 是 20 GB 而非 308 GB,但不是零算力**(32B 的 AAR 在 CPU 上分钟到小时级)。
- Llama 权重 gated,本轮 401;其 config 未核实,不进正文。
