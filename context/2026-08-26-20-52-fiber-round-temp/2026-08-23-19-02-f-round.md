## Checkpoint — 2026-08-23 19:07,四篇完成

**编号改动:原 F3 拆为 F3(纯分词器)与 F7(纯权重两张表)。** 理由是二者输入、成本、失败模式全不同,混编就是「F3 零成本」那句错话的来源。

**本轮实测的 config(✅)**:Qwen2.5-0.5B/1.5B/32B、Qwen3-32B、Qwen3-30B-A3B、DeepSeek-V2-Lite。**Llama 权重 gated,`config.json` 返回 HTTP 401**,其数值一律未进正文。

**网格掉出的两个真实缺陷,不掩饰:**
1. **主梯上 tie 与规模共变**(Qwen 全家小模型绑定、大模型不绑定),故 P5 须以 AAR 作协变量,且 3B/7B 的 tie 值决定断点位置(⬜)。
2. **32B 档做不到跨分词器**——Llama 无 32B 档,三个 32B 全是 Qwen 分词器族。取舍(严格同规模同分词器 vs 近似同规模跨分词器)交用户定。

**成本账的关键修正:P1/P2/P7 是 ≈20 GB 而不是 308 GB**(safetensors 按分片只取 `embed_tokens.weight` 与 `lm_head.weight`),但**不是零算力**:32B 的 AAR 是 152064² × 5120 的 argmax ≈ 240 TFLOPs,CPU 上分钟到小时级。

**写代码时看清的四处会静默出错的地方,已定死处置**(全部在 R3):bf16 argmax 会给出与 fp32 不同的答案 → 一律 fp32;152064² 输出 92 GB → 分块且维护全局索引;pad 行未训练 → 两个分母各报一次;**byte-level BPE 的 token 未必是合法 UTF-8** → 不隔离则「碎裂率」几乎全是这个 bug。

**两条要回填结论表:**
- **P7 是 P1 的机制,二者不独立。** Cauchy–Schwarz 只在 $\lVert e_b\rVert\le\lVert e_a\rVert$ 时保证 argmax 命中自己,故范数散布是锚对齐失败的原因。
- **byte-level 词表的 undecodable token 不在 $\Omega$(字符串集)里**,Q1 §1 的载体对这类词表须改为字节串。这是理论边界的一次真实收窄。

**一条预言弱化:P2 只能测「语料未出现」,不能测「不可达」**(枚举全部字符串不可能),语料规模成协变量。且碎裂 ≠ 不可达,不许混报。

**F2 从两臂变三臂:上界臂 $u^{\mathrm{glb}}$ 是 P5 跨规模可比性的前提**(绝对代价因 $d$ 与嵌入尺度不同而不可比,须用无量纲比 $\rho$),离流形参照是副产品。三个混淆项各配对照:范数(RMSNorm 吃掉 + $\varphi_0$ 单列)、离流形(当协变量分箱 + 上界臂给极端参照)、温度(扫五点 + 熵作第二协变量,顺带检验第 18 条)。

**F6 的成本报了实数**:32B 全参 + Adam ≈ 512 GB 优化器态,须 8×80GB。推荐「全参 8B + LoRA 32B」并明确两者结论不合并——**这是预算决定,不伪装成设计决定**。

**门:过。** 四篇均按四轴报成本、每条预言带阈值杀伤条件、三处硬上限(P6 归因只到「这一对」、32B 档同分词器、P2 只测语料未出现)明写。
